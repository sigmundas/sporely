# Taxonomy v3: authoritative bridge coverage, reconciliation and national names

Status: planned, not started. Decisions below were approved by the owner on
2026-09-27. No stage is authorized to modify production; each production step
needs its own explicit go-ahead, as in the taxonomy-v2 closeout.

"Taxonomy v3" is the name of this workstream, not a schema version.
`TAXONOMY_SCHEMA_VERSION` stays 2 unless a stage proves it cannot be additive.

- sporely-web `main` `3de2397`.

## Principles

Four things stay separate:

1. **Sporely concept identity.** Immutable `sporely_taxon_id`, allocated only
   by the registry, bound only by reviewed, evidenced reconciliation.
2. **Canonical nomenclature.** The COL-backed `canonical_scientific_name`.
3. **National nomenclature.** Preferred Norwegian/Swedish scientific names and
   vernaculars by language. Display and search metadata, never identity.
4. **Provider and publishing identities.** NorTaxa, Artsorakel raw ids and
   name snapshots, Dyntaxa, Artportalen, iNaturalist. Always namespaced, always
   provenance-preserving.

A name may suggest a reconciliation candidate. A name alone never proves one.
Exact scientific-name or authorship agreement never becomes automatic
cross-source identity (`identity-contract.md`,
`mapping_policy.continuity_rules.canonical_name_only`).

## Approved decisions (2026-09-27)

1. Group A (bridge coverage) goes before Group B (duplicate candidates).
2. Batch approval is allowed only for an explicitly enumerated, immutable
   candidate manifest. One review decision may approve the whole manifest, but
   it must produce an auditable per-association mapping for every member,
   pinned to the source releases it was reviewed against. It is never an
   evergreen rule that approves new taxa in a later source release. Evidence
   handling:
   - `reciprocal_accepted_synonymy`: strongest batch-review candidate;
   - `shared_synonymy`: batch evidence and statistics prepared for review;
   - `one_directional_accepted_synonymy`: individual review;
   - `no_published_cross_reference`: stays unresolved.
   The fail-closed bridge-emission architecture is preserved.
3. After new Group-A bridges are active, an explicit, idempotent repair pass
   re-resolves historical cloud `external_unresolved` observations, from
   preserved source + namespace + external id only. The owner does not have to
   open the observation.
4. Norwegian scientific display uses the approved NorTaxa preferred name when
   an approved NorTaxa identity exists; otherwise canonical COL. Canonical
   identity and canonical name never change. Search accepts both names.
5. Sweden follows the same architecture later: Dyntaxa preferred scientific
   name and Swedish vernaculars layered on the same Sporely identity. Dyntaxa
   is openly available (SLU Taxon Service API and Darwin Core download; the
   SLU checklist on GBIF is CC0 1.0), but the stage must pin, fingerprint and
   verify the actual archive and record its exact licence and citation.
6. Group-B work is "reconcile duplicate candidates", not "merge duplicates".
7. Stage order is as below.
8. National display fields are added alongside `canonical_scientific_name`;
   no schema bump unless additive is impossible.

## The two populations

Counts marked *(08.01)* come from
`database/taxonomy/evidence/taxonomy-v2-closeout/stage3-bridge-emission-coverage.json`,
which was computed against `tax-2026.08.01-01` and candidate `tax-2026.07.30-02`.
Stage 0 recomputes all of them against `tax-2026.09.26-02`.

**Group A — one concept, NorTaxa id not published as a bridge.** A COL concept
carries the NorTaxa id through the compiler's automatic exact match
(`note = cross_source_automatic_exact`). Automatic matches are not
authoritative, so the scoped export does not emit them, and
`resolve_taxon_external_id_v2` cannot resolve the NorTaxa id in production.
Every Artsorakel suggestion for such a species is saved as
`external_unresolved`.

- 19,807 such rows in the `tax-2026.09.26-02` SQLite.
- The production export carries exactly 3 `nortaxa_taxon_id` bridges: 53482 →
  7821, and 52369 plus its synonym 58722 → 83668.
- *(08.01)* In the cloud scope: 7,082 bindings, of which 5,193
  `no_published_cross_reference`, 1,888 `shared_synonymy` reviewable, 1 emitted.
- Example: Craterellus tubaeformis, Sporely 620306 (in the cloud), NorTaxa
  56227 unresolved.

**Group B — duplicate candidates.** A NorTaxa concept and a COL concept share a
canonical scientific name but are separate Sporely concepts. Name equality
only sized this population.

- 7,338 NorTaxa concepts (7,423 pairs) in the `tax-2026.09.26-02` SQLite.
- The COL side is in the cloud scope for 2,132 pairs; the NorTaxa side never
  is. The cloud scope contains only COL-canonical concepts (52,917 of 52,917),
  so a NorTaxa concept's vernaculars and ids reach the cloud only through
  reconciliation with a COL concept.
- Examples: Cantharellus cibarius (COL 168873 lacks "kantarell"); Conocybe
  vexans COL 617026 versus NorTaxa Pholiotina vexans 627000 (NorTaxa 58766,
  which lists Conocybe vexans as a synonym).

## Stage 0 — Coverage audit and v2 housekeeping

Repos: sporely-py. No production, schema or release change.

Scope:

- Regenerate `cross_reference_evidence.py` output and the bridge-emission
  coverage report against `tax-2026.09.26-02` and its pinned source archives,
  with a committed, reproducible command.
- Report Group A and Group B separately, each for the full release and for the
  cloud scope (`global_macrofungi_policy_v1`).
- Break reviewable Group A down by `reciprocal_accepted_synonymy`,
  `shared_synonymy` and `one_directional_accepted_synonymy`, with the
  distribution of shared-synonym counts per association.
- Write immutable candidate manifests, one per evidence class, each listing
  every association (source usage, target usage, Sporely id, evidence detail)
  and carrying a SHA-256 fingerprint and the source archive fingerprints.
- Place every regression species (table below) in a known class.
- Move `2026-09-15-taxonomy-v2-closeout.md` to `docs/plans/completed/` and
  correct its stale note that 0.9.24 is not tagged.
- Add to `docs/plans/INBOX.md` `## Taxonomy`: Group-A bridge coverage,
  national scientific names, historical unresolved-observation repair. Restate
  the existing "~7,300 duplicates" item with the Stage 0 counts.

Acceptance gate:

- Counts reproduce exactly from a clean checkout with the committed command.
- The manifests are deterministic: two runs give byte-identical files.
- Every regression species is classified.
- No policy, overlay, mapping or registry file changes.

## Stage 1A — Group-A authoritative bridge coverage

Repos: sporely-py (policy, emission, release). Cloud rows arrive only through
a later release built in Stage 6.

Scope:

- Present the Stage 0 manifests for review in the order `reciprocal`, then
  `shared_synonymy` (with its statistics), then `one_directional` one by one.
- On approval, generate one per-association reviewed mapping per manifest
  member, carrying the existing required fields (`reviewer`, `rationale`,
  `evidence_references`, `source_release_range`, and so on) and a reference to
  the approved manifest fingerprint. Where the records live (inline in
  `manual_mappings.yml` or in a batch file the same loader validates) is a
  design decision for this stage's review.
- `bridge_emission.py` emits only approved records with complete provenance,
  as today. Nothing is emitted from an evidence class alone.

Acceptance gate:

- Every emitted bridge traces to a per-association record and an approved
  manifest fingerprint.
- A candidate that is not in an approved manifest is never emitted, including
  a new taxon introduced by a later NorTaxa release (test with a synthetic
  additional source row).
- `no_published_cross_reference` associations stay unemitted.
- No `sporely_taxon_id` changes; the registry is untouched.
- Regressions: 53482 → 7821 and 52369 → 83668 unchanged; NorTaxa 56227 →
  620306 resolves once its association is approved; NBIC:56449 (the test's
  deliberately unresolvable id) stays unresolved.

## Stage 1B — Historical unresolved-observation repair

Repos: sporely-web (repair function or operator script, dry run, reports).
Runs only after a release with the new Group-A bridges is active. Needs
`sporely-security-reviewer`: it writes observation identity on behalf of
owners.

Scope:

- Select cloud observations with `taxon_identity_state = 'external_unresolved'`.
- Resolve each from its preserved `taxon_identity_source_system`,
  `taxon_identity_namespace` and `taxon_identity_external_id` against the
  active release, with the same authoritative resolver as the client.
- Exactly one authoritative match promotes the observation to `sporely_v2`.
  Raw provider id and name snapshot are preserved. Ambiguous, no match or
  error changes nothing.
- Never read scientific-name text for resolution.
- Dry run first, with a report of what would change; then the run, with a
  post-run audit report.
- Confirm against `docs/supabase-sync-contract.md` how a server-side identity
  change reaches desktop and other devices, and that it cannot be overwritten
  or overwrite local edits.

Acceptance gate:

- Idempotent: a second run changes nothing.
- The dry-run report and the actual changes match exactly.
- Every promoted row has one authoritative match and keeps its raw provenance.
- Security review passes.
- Regressions: a local-database fixture with observations holding NBIC:56227
  (promotes after Stage 1A), NBIC:58766 (unchanged unless Stage 2 approves a
  relationship), NBIC:56449 (unchanged), and a deliberately ambiguous id
  (unchanged).

## Stage 2 — Group-B reconciliation of duplicate candidates

Repos: sporely-py. Cloud effect through a later release.

Scope:

- Grade each Group-B pair with `cross_reference_evidence.py`; name equality is
  not evidence.
- Review under decision 2, in cloud-impact order: pairs whose COL concept is in
  the cloud scope first, and among those, pairs where the NorTaxa concept has
  vernaculars.
- Approved exact relationships become `concept_supersessions.yml` records
  (retire the NorTaxa concept append-only, re-key its names, vernaculars and
  external ids to the surviving concept) or manual mappings, as 52369 → 83668
  was done.
- Before any supersession ships, confirm read-only that no cloud observation
  references a retiring concept (expected: none, since NorTaxa concepts are
  not in the cloud scope). Desktop observations use the existing
  `database/audit_observation_identity.py` and repair runbook.

Acceptance gate:

- Every supersession has a reviewed record with evidence; no pair is
  reconciled by name alone.
- Retired ids stay in the registry and resolve to their survivor.
- Regressions: Cantharellus cibarius 168873 gains "kantarell" only through an
  approved relationship; Conocybe vexans 617026 / Pholiotina vexans 627000 is
  decided explicitly (approved, rejected or left open, with the reason), and
  NBIC:58766 resolves only if approved.

## Stage 3 — National preferred scientific names

Repos: both. Additive schema only.

Scope:

- Fill `preferred_scientific_name_no` (already in the SQLite schema, always
  NULL today, read by nothing) from the NorTaxa accepted name, only on concepts
  with an approved NorTaxa identity (a reviewed bridge or supersession, not an
  automatic match).
- Carry it to the cloud as optional, provenance-bearing display metadata next
  to `canonical_scientific_name`, via a new additive migration and scoped
  export; the exact shape (columns versus a keyed table) is decided in this
  stage's review.
- `search_taxa_v2` and the web label choose the national name by UI language
  and fall back to canonical COL. Search matches both names.
- Desktop uses the same rule.

Acceptance gate:

- No identity or `canonical_scientific_name` changes.
- `TAXONOMY_SCHEMA_VERSION` stays 2; compatibility contract checks pass.
- Regressions: Sporely 83668 shows "slank ringkjeglesopp (Pholiotina rugosa)"
  in Norwegian and "Conocybe rugosa" in Swedish; searching either name finds
  83668. A concept without an approved NorTaxa identity shows the COL name.

## Stage 4 — Dyntaxa as a national source

Repos: sporely-py (adapter, compiler), sporely-web (namespace in the resolver
and export if needed).

Scope:

- Choose the acquisition route (GBIF CC0 checklist or SLU download/API), pin
  the archive, fingerprint it, verify required fields, and record licence and
  citation. If SLU's custom export is used, verify its terms separately.
- Add a `national_sources/` adapter and generalize the NorTaxa-specific places
  listed in `database/taxonomy/README.md`.
- Generate matched, unmatched and ambiguous evidence; reconcile only under
  decision 2.
- Fill Swedish vernaculars and `preferred_scientific_name_sv` under the Stage 3
  rule.
- Verify, do not assume, how Dyntaxa ids relate to Artportalen ids.

Acceptance gate:

- Archive, licence and citation recorded and fingerprinted.
- No identity from name equality; every bridge is reviewed.
- Swedish names no longer depend solely on the frozen legacy database for
  bridged concepts.
- Existing NorTaxa/COL bridges unchanged.

## Stage 5 — Web and Android presentation follow-ups

Repos: sporely-web (Android is the Capacitor shell of the same code). Can run
in parallel with Stages 1–4.

Scope:

- Kraghätting: enable the `sporely-debug-artsorakel` snapshot, reproduce the
  NBIC:58766 suggestion, capture the raw candidate, and determine whether
  Artsorakel omitted the scientific name or the normalizer missed its field.
  No code change before the payload is captured.
- Decide whether Finds should indicate that an observation is

Acceptance gate:

- The Kraghätting mechanism is proven from the captured payload before any fix.
- Any label fix does not change identity handling.

## Stage 6 — Deterministic release and regression proof

Repos: sporely-py (build, bundle, probes), sporely-web (prepare only).

Scope:

- Build with `build_release.py` twice and require byte-identical output.
- Extend `tests/test_taxonomy_release_probes.py` with the regression table.
- Update `cloud_export` `PINNED_RELEASE_EXPECTATIONS`, prepare the scoped export
  and the production import payload.
- Production activation, then Stage 1B, each need a separate explicit
  go-ahead.

Acceptance gate:

- Deterministic double build; all probes and compatibility checks pass.
- The release delta lists only approved bridges, supersessions and display
  fields; no new or changed Sporely ids beyond approved supersessions.

## Open questions

- NorTaxa-only concepts with no COL counterpart never reach the cloud scope,
  which contains only COL-canonical concepts. Whether that should change is a
  scope-policy question outside this plan.
- Whether desktop `external_unresolved` observations need a matching repair
  pass, or already resolve against the desktop bundle, is to be checked in
  Stage 1B.
- The 448 Artportalen overlay cases and cloud exposure of Artportalen and
  iNaturalist ids remain INBOX items, not stages of this plan.
