# Proposed amendment to `mapping_policy.yml` (not applied; revision 5)

Line numbers refer to `database/taxonomy/policies/mapping_policy.yml` at
`19af384` (sha256 `a5a32984…`).

**S1 needs only part of this amendment:**
- the batch-manifest clauses P1, P4, P5 and P7;
- P10 (§5), new in revision 5.

P2, P3 and P6, the legacy clauses P8 and P9, and the future-release compiler
rule (§4) are deferred: S1 does not depend on them.

## 1. The conflict

The policy allows no name-based identity. The compiler
(`cross_source_mapping.py`, `automatic_exact`) binds by name anyway: 16,424
NorTaxa usages share a Sporely id with a COL concept today, 14,291 strict and
2,133 missing-authorship. Every clause below must change together, or the
policy stays self-contradictory.

## 3. Rule `deterministic_name_rank_authorship_v1`, revision 4

Applied per pair, NorTaxa concept or usage N and COL concept C. All of the
following must hold:

| # | Predicate |
|---|---|
| R1 | `nkey(N) == nkey(C)` and the ranks are equal |
| R2 | One same-rank twin on each side, as the validator's `one_to_one` requires. Pairs that are unique only after authorship filtering are excluded and listed in `A2-author-filtered`. They need a documented validator change before they can ever be batched. |
| R3 | NorTaxa `valid`; COL `accepted`. **Nomenclatural status on either side blocks:** NorTaxa `nomenclaturalStatus` ∈ {illegitimate, dubious, notvalidlypublished, orthographic, misapplied}, or COL `col:nameStatus` ∈ {unacceptable, doubtful, manuscript, not established}. These go to B sub-class `nomenclatural_status` (`scripts/rules.py`). |
| R4 | The authorship class from `scripts/authorship.py` rev 4, pinned by sha256. Rev 4 is fail-closed: sanctioning strips only `: Fr.`/`: Pers.`; citation stripping removes only a trailing year; list separators are significant; identical qualified strings are qualified; malformed parentheses are never batchable. Missing authorship needs two agreeing higher ranks **at every rank**. **A0:** identical, typography (structure kept: `Scop.: Fr.` ≠ `(Scop.) Fr.`), citation_stripped or sanctioning. **A1:** abbreviation, or missing authorship with at least two agreeing higher ranks. A1 is never executable without expert validation, because no standard author-abbreviation reference exists locally. **Never** batchable on either side: `nom. prov.`, `prov.`, `ined.`, `comb. ined.`, `ad int.`, `?`, `ss.`, `sensu`, `non`, `auct.`, `p.p.`, `pro parte`, `s.l.`, `s. str.`, `emend.`, `excl.`, `incl.`, `fide`, `nom. illeg./inval./nud./rej./superfl.`; also `ex_author_differs`, `basionym_omitted`, `partial_list`, `conflicting`. |
| R5 | No disagreement among populated phylum, class, order and family. Variant `v1p` (decision D3) allows an order or family difference. |
| R6 | No competing synonym placement of the same name and compatible authorship in either source |
| R7 | No conflicting iNaturalist or Artportalen ↔ Dyntaxa id |
| R8 | The survivor carries no other NorTaxa accepted id |
| R9 | Children no longer block. Once the parent fix is in, the builder re-parents them automatically through re-keyed usages (`nortaxa-parent-link-defect.md` §5). Re-parenting is computed **per release stage**, against what that stage and the earlier stages retire. A pair that would need an operation in an A0 or A1 stage moves to A2. The operations are listed in `manifests/reparent-ops.jsonl` with their stage. |
| R10 | Pins: release, archives, policy, rule file, comparator sha256. Never evergreen. |

**Fail-closed.** These are never bound:
- a candidate with no backbone match, which becomes a provisional national
  concept under `unresolved_supported_source_taxon`, as today;
- a candidate with several matches, which is kept separate;
- a candidate failing any predicate;
- a candidate whose manifest pin or hash no longer matches the compiled
  inputs.

The compiler refuses the build if a manifest member no longer satisfies
R1–R8 on the compiled inputs.

## 4. Future releases: compiler change (required, in R1 of the plan)

`compile_release.py` must stop applying `automatic_exact` aliases. A NorTaxa
usage is bound to a backbone concept only if one of these holds:
1. it is a member of an approved manifest whose pins match the compiled inputs;
2. it is a legacy binding (P8) already in the registry;
3. an approved manual mapping covers it.

Otherwise it keeps its own concept, or is newly allocated one, and appears in
the next generated candidate manifest. The trade-off: a new NorTaxa release
may temporarily create duplicates. That is accepted as fail-closed.

The compiler must also **verify each approved manifest's pins against the
compiled inputs**: the release, both source archives' ids and sha256 values,
the policy sha256 and the rule/comparator sha256. Today
`compile_release.py:388–450` checks only the manifest file's own pins. This is
an R1 task.

Build test H11 fails if any `cross_source_automatic_exact_*` alias is applied
outside cases 1 to 3.

## 5. P10: usages inherited through a supersession (revision 5, S1)

**The defect.** `compile_release.py:1083–1092` (at `19af384`) re-keys every
usage allocated to a superseded concept. It sets the evidence class of every
one of them to `reviewed_supersession`, a class that bridge emission accepts
(`mapping_policy.yml` L48). For S1 that would publish 1,175 NorTaxa synonym
usages as reviewed bridges, although the approval covers only the 988 accepted
pairs. Of those synonyms:
- 1,016 have a blocked nomenclatural status;
- 38 are qualified;
- 7 are unpublished or doubtful.

**New key `inherited_usage_under_supersession`:**

> When an approved supersession re-keys a concept, only that concept's own
> anchor usage, the accepted usage the approved record names, becomes
> `reviewed_supersession`. Every other usage moves to the current concept as
> a name. It keeps its own evidence class (normally `intra_source_synonym`,
> which is rejected for emission), its taxonomic and nomenclatural status and
> its identifier, and it is marked `inherited_via_supersession` with its
> `superseded_from` id. It is never emitted as an authoritative bridge unless
> a separate per-association decision approves it. The key applies to ledger
> records carrying `inherited_usages: "names_only"`; every record created
> from a batch manifest must carry it.

Existing records keep their current behaviour until a separate decision. The
shipped release publishes 4,779 such synonym bridges through 1,353
supersessions.

**Compiler.** In the supersession branch, set `bridge_evidence_class =
reviewed_supersession` only when `allocation.kind == "anchor"` and the record
says `names_only`; otherwise keep the class and set `inheritance`. The
change also needs:
- `ConceptSupersession` to carry `inherited_usages`;
- `verify_supersession_manifest_approvals` to require `names_only` for the S1 manifests;
- `source_usages.jsonl` to gain `inheritance` and `nomenclatural_status`, taken from `record.raw`.

**Builder.** No change is required: the existing rejection of
`intra_source_synonym` already withholds the bridge. Showing the provenance
in `note` is optional. It would require updating the exact `note` match in
`audit_stage0_coverage.py:89`.

**Data model.** Every part is representable without a schema change:
- names in `scientific_name_min`;
- NorTaxa ids in `taxon_external_id_min` with `id_role = synonym`;
- no row in `taxon_external_id_text_min`;
- the cloud export carries `note` verbatim.

**Proof.** `scripts/s1_synonyms.py` executes the compiler lines verbatim and
then the real `build_sqlite_candidate._build_into`:

|---|---|---|
| Sample of 4 retirees | 20 bridges | 4 bridges; names and integer ids unchanged |
| All of S1 | 2,163 bridges | 988 bridges |
